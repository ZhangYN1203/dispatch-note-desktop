# 订单与库存使用说明

## 开单

核心区域录入客户、日期及常用发货信息，运输与签收等选填字段可展开。发货单位、发货电话、仓库和制单人可保存为默认值，之后新单自动带出。订单列表“更多 → 复制开单”生成新单号、新日期和草稿状态，保留来源商品及价格；选择客户商品时仍使用其专属价格。保存前离开有未保存提醒。

草稿可编辑、删除；确认后的订单要先退回草稿再修改。商品名称、规格、箱规、单价存入明细快照，修改商品资料不会改变已保存单据。

## 确认、发货与作废

1. 草稿核对完成，在“更多”中确认，确认不扣库存。
2. 实物备齐后选择“发货”，为每条明细明确选择成品库存批次。带商品编码的批次必须与明细编码一致，单位必须一致；无编码的旧批次由操作人核对名称和规格。
3. 整单库存足够才提交，库存、流水、生产状态、订单状态同时生效；中途失败全部回滚。
4. 未发货取消可作废并填写原因；已发货只有在整单货物实际退回后，才勾选退回确认并作废，恢复到原批次一次。重复发货、重复作废会被拒绝。
5. “状态记录”查看确认、退回草稿、发货和作废的时间及原因。

当前不支持拆分批次、分批发货和部分退货。每条明细从一个批次扣减全部数量。关联新订单的生产成品应从订单入口发货，避免库存出库和订单发货重复记账。

## 原料与生产

原料期初数量记录期初流水；后续余额通过入库、领料或出库调整，不能直接覆盖。生产依次经过待生产、生产中、已完成、已入库；仅生产中的任务可领料，仅已完成的任务可入库。入库可关联商品编码以确保发货时核对一致。生产入库、手动出库和原料操作均由主进程重新校验实时库存。

## 升级旧资料

第一次升级会在数据目录 backups 下保存原始 `*-schema-upgrade.db` 文件。它用于配合旧版本回退，不能通过新版完整备份入口直接恢复。新版仍支持创建和恢复新版完整备份。

已有订单标记为“历史单据”，可查看、打印、复制成新草稿；不推断过去是否发货，也不追溯扣库存。已有明细箱规从升级时的商品资料补齐一次，升级前已丢失的历史箱规无法还原。

在用生产库存保持原 ID，统一保存在 SQLite 的 production_records。旧备用 SQL 库存表只保留归档并显示提示，需人工核对原始记录和实际盘点；不会按名称自动合并或重复入库。原 IndexedDB 迁移仍保留来源数据。

汇总默认排除作废，可选择只统计已确认或已发货；默认金额包含尚未发货订单，不能直接当作实际出库或销售确认金额。
