# 1.4.2 功能验收记录

日期：2026-11-28。使用隔离临时 userData、虚构业务资料，在真实 Electron 窗口内操作页面按钮和表单，经 preload/IPC 写入 SQLite；没有修改使用者业务库，也没有发送真实打印任务。

## 发现并修复

| 问题 | 修复及验证 |
| --- | --- |
| 默认表改价入口不明确，基础价不同步 | 显示“修改价格”；默认价与商品基础价、日志事务提交，撤销同步恢复，专属价和历史单不变 |
| 新增商品没有单价输入框 | 增加单价；空价、负数、非有限值及超限拒绝；零价可保存；失败在弹窗内提示 |
| 新增商品同步价格表失败可能留下半条记录 | 商品与全部价格表一起事务保存，注入失败验证全部回滚 |
| 修改商品品牌提示成功但未保存 | 补传品牌字段，真实界面重查核对 |
| 改商品编码后撤销价格无效 | 同步改价日志编码；商品、价格引用及日志一起提交，注入失败验证回滚 |
| 改日期后导出旧汇总，查询在途还会回填旧结果 | 修改日期/状态立即失效结果与查询版本，旧响应不覆盖新条件；核对明细、合计导出内容 |
| 库存搜索失焦，筛选下拉/复选框显示复原 | 保留筛选状态、输入焦点和选区，连续输入及空结果恢复通过 |
| 原料缺少资料编辑入口 | 新增资料编辑；库存只读；历史流水不变；并发出入库后拒绝旧表单覆盖 |
| 收发存遗漏原料期初录入 | 按期初流水日期计入本期或期初，核对期末与库存；日期无效清除旧报表 |
| 旧迁移库存缺失原始流水，报表易误解 | 显示历史不完整及当前库存提示，不编造未知日期的期间余额 |

## 复验方法

```sh
npm test
npm run test:audit
npm run check:public
```

界面脚本输出临时证据目录，保留数据库、导出的 Excel/PDF 和 JSON 验收结果。打印失败、缺失打印机、无效数量和坏备份的错误日志属于主动注入的验收场景。

## 实际验证边界

- 打印经真实 Electron PDF 输出核对页面尺寸、分页、边距和字号；打印机调用用可控替身核对参数及失败提示。未验证真实硬件走纸、驱动缩放和套打偏移，交付前仍需使用目标打印机打一张校准页。
- 独立版从空库启动验证，更新沿用应用身份；没有执行安装向导覆盖使用者当前安装目录。
- 旧数据缺失的历史流水无法从当前余额可靠恢复，报表保留提示。
- 公开源码、样例和截图仅使用虚构资料；真实数据交付包与公开源码分开保管。
